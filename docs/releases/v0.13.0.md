# Tycho v0.13.0

## Safer agent workflows

- **Truthful context-pressure warnings.** Tycho warns from reliable active
  context evidence and shows a measured percentage only when the harness also
  reports a valid limit. Operators can keep going, start a clean clone, start
  with a concise handoff, or archive with the existing safeguards.
- **Blocked queue controls.** Local CLI, remote CLI, and Remote UI controls can
  process selected stable-ID entries or all pending entries when agent state
  blocks automatic dispatch. Exact snapshots, FIFO ordering, confirmations,
  and delegation protections prevent work from moving under stale controls.
- **Recoverable failed batches.** Failed queue claims remain inspectable and
  can be retried or discarded when safe. Discard records audited dispositions;
  protected delegation callbacks must be retried.
- **Partial work release.** A Partial result keeps its truthful status and now
  settles delivered QueueWork with source-appropriate defaults. Later ordinary,
  delayed, delegated, and mixed work can continue in FIFO order.
- **Partial scheduled runs.** A recurring schedule records Partial as its last
  outcome, clears failure state, and remains scheduled for its next run. Partial
  does not send a failure notification or stop the schedule.
- **Stale Ruby-path recovery.** When an update removes a versioned Ruby path
  held by Tycho, agent launches resolve the current `ruby` on `PATH`. If Ruby
  is unavailable, Tycho gives recovery steps; the failed queue claim remains
  inspectable so the operator can restart Tycho and retry it.
- **Managed PR diff catalogs.** Add or remove pull requests through local or
  remote `agent pr-diff` commands and the Remote UI. Detaching a pull request
  preserves source attachments and shared immutable snapshots.

## Remote UI and reliability

- Render trusted pull-request context as readable validated cards. Unexpected
  or malformed envelopes stay escaped as plain text.
- Return detail-page prompt submissions to Conversation immediately with a
  pending message. A failed request restores the exact route, draft, focus, and
  attachments; duplicate submission from the active form is blocked.
- Remove unavailable-peer blocking from normal navigation, defer cold tool and
  skill discovery, cache archive-local reads, and add an optional deterministic
  profiler for every Remote UI route.
- Make non-assistant activity quieter and make Summary status, prose, and
  actions easier to scan. Remove duplicate Summary text and bound the mobile
  preview to five lines with stacked actions.
- Show a normal Summary card when structured output is missing or invalid.
  Only the detail view can show bounded, redacted fallback assistant context.
- Download attachments with their original safe filenames. Control bytes,
  traversal forms, separator-only names, long values, duplicates, Unicode, and
  legacy records use validated normalization or a safe fallback.
- Serialize notification-ledger changes across processes and retain queue-failure
  targets, read state, recovery state, archive routing, and missing-target
  fallback without duplicate pushes or lost records.

## Metrics and maintainer workflow

- Price `openai.`-qualified custom Codex model names with the canonical OpenAI
  table while retaining the configured model, normalized priced model, and
  authoritative source. Unknown qualified models remain explicitly unpriced
  and keep their token telemetry.
- Require the pinned local CI signoff on the exact pushed pull-request head.

## Compatibility and upgrade notes

- No manual migration is required for projects, schedules, agents, delegation,
  QueueWork, notifications, pull-request catalogs, attachments, credentials,
  or memory.
- Update each Tycho-owned skill from **Settings → Skills** after upgrading. The
  packaged guidance includes failed-batch discard, Partial settlement, and
  context-pressure handoff behavior.
- Existing queue records stay valid. Note that Partial now consumes delivered
  work; failed, blocked, and input-required runs still retain unresolved work.
- Existing attachment records and notification ledgers load without conversion.
  Legacy attachments receive a safe download-name fallback.
- v0.11.0 remains the final Intel macOS bottle. v0.13.0 publishes Apple Silicon
  macOS and Linux bottles; Intel users can continue running from source.

After independent review and merge, follow `docs/RELEASING.md`: tag `v0.13.0`
from updated `main`, create the GitHub release with this file, then update the
Homebrew tap for `v0.13.0` and verify the Apple Silicon macOS and Linux bottles.

## Rollback

Before publication, close the release-preparation pull request or revert its
version-and-documentation commit. After publication, do not move the public
tag. Cut a corrected patch release for a harmless issue. For a severe issue,
mark the GitHub release as a prerelease or delete its release page, then publish
a corrected patch from `main`. The first patch after `v0.13.0` is `v0.13.1`.
