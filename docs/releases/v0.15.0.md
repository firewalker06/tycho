# Tycho v0.15.0

## Send large prompts through stdin

- Codex, Claude, OpenCode, Pi, and agy managed runs now receive prompts through
  stdin. Prompt text stays out of process arguments and environment variables.
  New runs, native resume, and structured-output correction use the same path.
- Preserve multiline text, Unicode, and trailing newlines, including in the C
  locale. Stdin supports prompts above 1 MB without OS argument limits.
- Custom harness profiles can select version 1 `argv`, `stdin`, or `file`
  transport. File mode uses private files with cleanup after completion,
  cancellation, and crash recovery. See [custom harness profiles](../CUSTOM_HARNESSES.md).
- Managed runner process titles now show the agent key instead of inline Ruby.
  Raw logs and canonical memory still contain the prompt. Saved command
  descriptions redact prompt text.

## Recover messages and inquiry answers

- Confirm messages with small acceptance receipts. Exact retry keeps the same
  request ID and does not add a second message after acceptance.
- Clear stale retries when server reads prove acceptance. **Cancel retry** stops
  browser retry across tabs that share browser storage. It keeps accepted work.
- Show a submitted inquiry answer in Conversation at once, with a pending marker.
  Show recovery controls after failure or during retry, without a second panel
  during normal sends.
- Keep answer fields, feedback, and files for retry after uncertain replies,
  reload, and navigation. Clear stale rejected answers when an inquiry closes
  or is replaced. Preserve newer inquiry drafts and files.
- Manual queue controls confirm only the message IDs proved by the result.
  Partial or uncertain results keep recovery controls. Queue rows show relative
  wait times, processor status, and the reason work must wait.
- Save schedules with one background refresh. Late replies preserve newer
  records, readers, and drafts.

See [inquiry answer recovery](../INQUIRY_ANSWER_RECOVERY.md) for limits.

## Start agents with less waiting

- Quick Agent opens an editable form before local and peer options finish loading.
  Late options preserve your text and explicit choices.
- Create opens a pending Conversation at once. Same-ID retry recovers the
  accepted agent without creating or starting a second one.
- Historical archive gaps no longer block new agent creation when they predate
  creation receipts. Older archive health has a separate warning.
- Project forms keep their project context without a redundant selector.
  Remote hosts are in Options, and actions stay visible in a scrolling form.
- Project-level `agent_templates` now take effect. Invalid entries cause a config
  error. A missing template key produces a warning before fallback.

## Read and navigate in Nord Light

- Choose Dark, Light (Nord), or System in Settings > Configuration > Appearance.
  Dark remains the default. The saved choice applies before first paint and
  follows other tabs. System follows the OS appearance.
- Light mode includes readable Tycho logos and matching document previews.
- Filter attachment lists by All, Images, Files, or Links. Keep code lines intact
  and format single-line JSON only when the conversion is lossless.
- Delegated groups start collapsed in the logo menu. Archived or disconnected
  linked agents have a separate collapsed group. The badge counts active links.
- Conversation and full Summary show saved delegated actions with target links,
  host and project details, and clear Started, Queued, and Sent labels.
- Copy Session ID copies the stable Tycho agent key from the Conversation header.
- Reduce repeated helper text and utility borders. Keep keyboard focus visible.
  Inquiry controls have space for their focus rings, including beside attachments.

## Read Remote UI data faster

- Agent lists, detail, conversation, and attachment reads use committed snapshots
  without waiting for unrelated lifecycle maintenance.
- Initial Conversation content loads before nonessential setup and schedules.
  Attachment reads and downloads can proceed during other agent work.
- Pause new polling while the window is hidden or unfocused. Let an in-flight
  poll finish so the status does not stay on Refreshing.
- Refresh project Git metadata only when a detail view needs it. Share a
  10-second cache and at most two background workers. Leaving the view cancels
  demand. Unknown or failed fields do not appear as Clean.
- Protect server worker slots with a one-second header deadline and a limit of
  24 open worker connections per peer address. Both limits are configurable.
- Add authenticated server diagnostics for admission, worker use, store lock
  waits, route time, and response writes. See [serve diagnostics](../SERVE_DIAGNOSTICS.md).
- Add an optional Interaction Profiler for repeatable browser timing reports.
  It is separate from required local CI. See [the profiler guide](../REMOTE_UI_INTERACTION_PROFILER.md).

## Use the experimental agy harness

- Add native Antigravity CLI (`agy`) events, conversation resume, structured
  results, model discovery, and skill installation.
- Authentication status remains unknown. Saved reasoning effort is ignored.
  Sandbox isolation is unverified. This adapter is experimental and is not
  ready for production. See [agy support and limits](../AGY.md).

## Cost estimates

- Derive new Claude resumed-run estimates from compatible native session totals
  instead of adding restored totals again. Missing evidence stays unavailable.
  Saved historical estimates are unchanged.
- Summary shows the saved cumulative estimated cost through the selected run,
  including partial and missing-value states. These values are estimates, not bills.

## Compatibility

- Ruby 4.0.9 or later is still required. No new Ruby gem dependency is added.
- Pi now targets `@earendil-works/pi-coding-agent` 0.84.4 and its RPC contract.
  Older versions that emit only `agent_end` are unsupported. Restricted Pi modes
  still use a tool allowlist; they do not provide a filesystem sandbox.
- Validated transport baselines are Codex CLI 0.166.0, Claude Code 2.1.312,
  OpenCode 1.19.3, and agy 1.5.1. Later versions must preserve their documented
  input, event, and resume contracts.
- Custom wrappers must accept the selected adapter's stdin contract. Wrappers
  that need a final prompt argument can select version 1 `argv`. A custom
  profile named `agy` must be renamed because that name is now built in.
- No manual data migration is required. Existing projects, agents, schedules,
  queues, memory, credentials, and attachments remain valid. Old agy bridge
  agents are historical records; create fresh agents for native agy use.
- Bottles still target Apple Silicon macOS and Linux. v0.11.0 remains the final
  Intel macOS bottle. Intel users can run from source.

See the [v0.15.0 upgrade guide](../UPGRADING.md#0150) for required checks.

## Validation

The release-prep PR records the full `bin/test` result and the required
`signoff/tycho-bin-test` status on its exact pushed head. The suite uses temporary
Tycho state and blocks real Web Push transport. Release preparation changes
version and documentation only; it does not repeat every feature browser check.

GitHub release, Homebrew publication, website delivery, and social work have
separate results. Release preparation does not complete those surfaces.

## Rollback

Before publication, revert the version and documentation change if required.
After publication, keep the public tag fixed and issue a corrected patch.
For a severe fault, follow the [release runbook](../RELEASING.md#corrections).
