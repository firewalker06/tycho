# Tycho v0.14.1

## Group agents by delegation

The relevancy Agents list now groups delegated agents under their parent.
Parents with recent activity appear first. Children appear in recent order
within each parent. Search results and explicit sorts stay flat, so you can
still find an agent by its ranked match.

## Recognize each harness

Remote UI shows the official Claude, OpenCode, and Pi marks, and the OpenAI
blossom for Codex, beside harness names. Agent rows, agent cards, agent
detail, and Settings use the same label. Provenance is in
[docs/HARNESS_LOGOS.md](https://github.com/firewalker06/tycho/blob/main/docs/HARNESS_LOGOS.md).

## Trust the Remote UI state

- Archived agents leave active views as soon as archive is confirmed. If the
  request fails, the agent returns with an error message.
- An answered inquiry no longer reappears when you revisit an agent.
- Started, sent, and queued notices use clear labels, and the project name
  appears beside Host.
- Git state shows **unknown** instead of **clean** until every git field is
  valid in Remote UI, the CLI, and the terminal rows.

## Read faster on large installations

Remote responses use shared caches for project git metadata, schedules, setup
summary, project reads, the agent list, and parsed conversation blocks. Git
calls are bounded to 5 seconds, and a failed read keeps the last good value.
Conversation opens with the newest 50 blocks and loads older pages as you
scroll. Remote requests run concurrently, and the UI polls only the visible
screen. Slow requests (500 ms or more) are logged with their stage split.

## Name agents and start Quick Agent faster

Agents receive a name from their first structured result when they have only a
default name. A custom name stays unchanged. Quick Agent keeps the name in a
collapsible Options area, remembers project defaults, and keeps the current
project visible. Set an optional default project in Remote UI Settings >
Configuration.

## Fixes

- Clone and archive actions archive the source correctly.
- Summary details keep idle-stop reasons.
- Terminal delegation reports are preserved before a callback resumes the parent.
- Mermaid previews use Mermaid 12 Neo styling with dark Redux colours.
- macOS startup works with relocatable Ruby installs.
- JWT and DOMPurify dependencies are updated for published security advisories.
- `bin/test` clears inherited managed-agent variables.

## Compatibility

- **Ruby 4.0.9 or later is required.** v0.14.0 documented Ruby 3.2 or later.
- **`jwt` (`>= 3.2.0`, `< 4`) is a new direct gem dependency.** v0.14.0 documented
  that no new gem dependency was added.
- The managed agent result schema adds the optional `agent_title_suggestion`
  field. Existing results remain valid.
- The example `hq.yml` adds an optional `quick_agent.default_project_key`. Blank
  keeps the first available project.
- No manual data migration is required. Existing projects, agents, schedules,
  queues, memory, credentials, and attachments remain valid.
- Bottles still target Apple Silicon macOS and Linux. v0.11.0 remains the final
  Intel macOS bottle. Intel users can continue from source.

See the [v0.14.1 upgrade guide](https://github.com/firewalker06/tycho/blob/main/docs/UPGRADING.md#0141)
for verification commands.

## Validation

Release validation covers the complete `bin/test` suite on the exact pushed
commit, version reporting, and the agent result schema. The release-prep PR
records the commit, test receipt, and the `signoff/tycho-bin-test` status.

Website delivery and Homebrew publication are separate gates. This note does not
claim either surface is complete.

## Rollback

Before publication, revert the version and documentation change if required.
After publication, keep the public tag fixed and issue a corrected patch
release. For a severe fault, follow the correction process in the
[release runbook](https://github.com/firewalker06/tycho/blob/main/docs/RELEASING.md).
