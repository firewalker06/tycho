# Tycho v0.16.0

## Keep current work in Focus

- Add a durable Focus document for each agent. Read and replace ordered sections
  with `tycho agent focus`, locally or with `--server`. Revision checks protect
  concurrent edits; exact retries are safe.
- Read Focus in its own Remote UI panel. Keep panel choices across refresh and
  navigation. Archive retains Focus; new clones start empty. Focus is separate
  from Summary and the transcript. See [Agent Focus](../AGENT_FOCUS.md).

## Store queues centrally

- Move pending entries, claims, QueueWork batches, dispositions, and staged
  delivery into one durable queue store with transaction recovery. Preserve
  legacy queue identifiers, order, authority, and completion evidence.
- Read legacy empty placeholders correctly and keep missing nonempty references
  as errors. A damaged unrelated archive queue no longer blocks creation-receipt
  lookup for a valid agent.
- Add local `queue-work cleanup-migrations` dry-run and explicit `--apply`.
  Remove only eligible empty migration audit receipts; retain 100 and remove at
  most 1,000 per apply. Queue records and completion proof stay intact.
  See [queue storage](../QUEUE_STORE.md) and [receipt retention](../QUEUE_MIGRATION_RETENTION.md).

## Manage projects and schedules

- Create projects in the Remote UI under the server user's home. Exact request
  replay prevents duplicate registration. Rejected forms keep their input and
  focus. Directory ownership, permissions, ACL, and local filesystem checks can
  reject unsafe or unsupported locations. This boundary trusts same-user and
  root processes. See [project creation](../REMOTE_SERVER.md#manual-project-creation).
- Delete projects through a confirmed background job with saved progress and
  explicit retry. Default deletion archives agents and identified logs. Optional
  permanent removal deletes identified archives; the workspace files stay on
  disk. All schedule references, including archived schedules, must be removed
  first. See [project deletion](../PROJECT_DELETION.md).
- Give Schedules a dedicated page, shared header controls, and a clear empty
  state. Keep mobile creation inline with the header menu.
- Add `tycho schedule archive KEY` and `schedule list --include-archived`.
  Keep configuration and history while hiding a stopped schedule from active
  lists. Preserve stopped target intent when the scheduler starts.
- Allow explicit one-time queue processing for an inactive schedule without
  resuming automatic scheduling. See [scheduled runs](../SCHEDULED_RUNS.md).

## Use DeepSeek Harness

- Add the native `dsh` adapter with stdin prompts, JSON events, native session
  resume, structured-result validation and correction, and an offline model
  catalog. Custom profiles can use `adapter: dsh` with stdin transport.
- The contract targets developer-preview `@deepseek-ai/dsh` 0.2.2-rc.1 and
  requires Node.js 24.9.0 or later. Authentication readiness stays unknown;
  model discovery does not prove account access. Tycho does not certify native
  sandbox confinement. Interactive terminal chat, Tycho skill installation,
  and the typed sleep circuit breaker are unsupported for dsh.
- Add official DeepSeek and Antigravity marks.
  See [DeepSeek setup and limits](../DEEPSEEK.md).

## Set themes and image backdrops

- Select independent Dark and Light palettes, edit custom JSON themes, and use
  the Themes gallery to import, update, share, and remove palettes. Dracula and
  Nord remain the defaults. System follows the OS appearance.
- Add bundled photo themes, vector scenes, and still or slow backdrop motion.
  Reduced motion stops drift. Bundled image credits and licenses ship with assets.
- Store uploaded backdrops in a bounded server image library. Manage PNG images
  with `tycho appearance images`, locally or with `--server`. Browser upload
  also converts JPEG and WebP to PNG.
- Keep palette selection and image adjustments specific to each browser.
  Existing browser-only images stay private until **Upload local image** is
  selected. Portable palette JSON has no image references.
  See [appearance and image limits](../REMOTE_UI_APPEARANCE.md).

## Read and use the Remote UI

- Show PR diffs as bounded fetches finish. Keep Mermaid previews across Summary
  refreshes. Render Summary links as attachment rows.
- Resolve local Markdown images in Summary and attachments through authenticated
  reads. Reject private paths and workspace-escaping symlinks; outside-workspace
  images must be registered attachments.
- Contract the desktop sidebar in split views and keep content panels readable
  at limited widths. Improve mobile composer actions and navigation, search
  focus, and startup animation and loading text.
- Remove redundant Conversation and Schedules background panels. Rotate three
  mascot expressions in the Now empty state, with reduced-motion support.
  See [Now empty state](../NOW_EMPTY_STATE.md).

## Compatibility and upgrade

- Ruby 4.0.9 or later remains required. Run `bundle install` for the new explicit
  `chunky_png` and `fiddle` dependencies. The dsh key is now built in; rename a
  conflicting custom profile before using it.
- Queue storage migrates automatically at first lifecycle load. Stop all TUI,
  server, scheduler, and other writers together before deployment. Back up the
  complete logs directory first. Never run an older writer against migrated
  state, restore one state file alone, or delete the queue store to retry.
- Existing agents, schedules, native sessions, credentials, and attachments are
  retained. New Focus and server image storage need no manual conversion.
- Apple Silicon macOS and Linux remain the bottle targets. v0.11.0 remains the
  final Intel macOS bottle; Intel users can run from source.

See the [v0.16.0 upgrade guide](../UPGRADING.md#0160).

## Validation and publication

The release-prep PR records full `bin/test` results and the required
`signoff/tycho-bin-test` status on its exact pushed head. Tests use isolated
state and block real Web Push delivery. Fixture isolation is stronger in this
release, including optional harness checks. Preparation changes only version
and documentation, so it does not repeat feature browser tests.

The source range is [v0.15.0 through the final mascot change](https://github.com/firewalker06/tycho/compare/v0.15.0...6441d605a1187401e9eed3a730db424a187f2e59).
GitHub release, Homebrew, website delivery, and social work each require a
separate result. Publication is pending operator approval.

## Rollback

Before publication, revert this version and documentation change if required.
After publication, keep the public tag fixed and issue a corrected patch.
A runtime downgrade after queue migration requires a coordinated restore of the
complete pre-upgrade backup with all writers stopped. Recover any pending
version 2 cleanup intent with the new version before a downgrade. See
[queue recovery](../QUEUE_STORE.md) and the [release runbook](../RELEASING.md#corrections).
