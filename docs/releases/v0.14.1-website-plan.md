# Tycho v0.14.1 pre-tag website plan

This plan completes the pre-tag website gate in [docs/RELEASING.md](https://github.com/firewalker06/tycho/blob/main/docs/RELEASING.md#required-website-delivery). It is planning evidence only. No site change is made here, no tag is created, and no deployment is made. ## Changed feature claims for the site

These claims are stale or new for v0.14.1. Each one needs a site edit or a confirmed exact-tag check.

1. Ruby floor. `src/content/docs/docs/getting-started/index.md:12` says "Ruby 3.2 or newer". It must read Ruby 4.0.9 or newer (`hq.gemspec`).
2. Version pins. Getting Started pins `git clone --branch v0.14.0` (line 57) and `tycho --version` reports `0.14.0` (line 34). Both become v0.14.1 after the tag exists.
3. Homebrew claims. The site lists "Homebrew bottles for v0.14.0" (lines 10 and 19). Do not claim v0.14.1 bottles until the tap publishes them and an installed check confirms them. Keep the Apple Silicon macOS 26-or-newer and x86_64 Linux targets, and keep Intel macOS on the v0.11.0 final-bottle note.
4. Upgrade notes. Add the v0.14.1 notes: the Ruby 4.0.9 floor, the new direct `jwt` gem (`>= 3.2.0`, `< 4`), the optional `agent_title_suggestion` schema field, and the optional `quick_agent.default_project_key` setting.
5. Reference page. `src/content/docs/docs/reference/index.md` describes "Tycho v0.14.0 ... commit 8d813dc". Update it to v0.14.1 with the exact tag commit, only after the tag exists.
6. Remote UI and Agents. Describe the delegation-grouped relevancy list, harness marks, the STARTED/SENT/QUEUED notice labels, the Quick Agent Options area, and Settings > Configuration for the default project. Check each claim against the exact tag before it is published.
7. Homepage version. `src/pages/index.astro:35` sets `currentVersion = 'v0.14.0'`. The badge must link to `https://github.com/firewalker06/tycho/releases/tag/v0.14.1` after the tag exists.

## Planned checks (after the tag and operator merge)

1. Resolve the exact `v0.14.1` tag and commit. Export it with `git archive` outside any checkout. Capture only from that export.
2. Recapture or replace the eight images marked "Recapture" or "Replace" with the product capture helpers at the exact tag, using synthetic fixtures and isolated state. Record viewport, browser version, fixture version, and output SHA-256.
3. Run `corepack pnpm install --frozen-lockfile`, `corepack pnpm build`, `corepack pnpm check:links`, and `git diff --check` using the site's pinned Node and pnpm.
4. Check desktop and mobile in Chrome. Cover the homepage version and release links, the carousel, the changed images, the Getting Started, Configuration, Reference, and Delegation pages, overflow, and keyboard access.
5. Open a draft site PR with What, Why, How, and Screenshots. Obtain independent review of the exact pushed head. The operator merges.
6. After merge and deployment authorization, deploy with `scripts/deploy-pages.sh`. Verify production HTTP, version, assets, and links. The rollback target is the previous verified deployment `7e1ed5d8-a9a2-4467-a43d-1ca1db4a1563`.
