Context-pressure warning and safe follow-up actions

Tycho now warns only when a managed harness supplies evidence of material context pressure. It does not convert cumulative token totals into a false context percentage.

Harness-neutral evidence model

EvidenceTycho stateWarning rule
Harness reports active tokens and an active context limitMeasuredWarn at 80%; critical at 95%
Harness reports compaction or an explicit overflowMeasured or reportedWarn without an invented percentage
A later run has no active-context telemetryStaleDo not reuse an old percentage
Only cumulative usage exists, or the harness is unsupportedUnknownDo not warn

Codex supplies active-context token counts and a model window. Claude and Pi can supply compaction events. OpenCode usage totals do not supply a reliable active window, so Tycho keeps that state unknown unless it receives a direct compaction or overflow event.

Operator actions and safety

  • Keep going acknowledges only the current signal. A changed signal can warn again.
  • Clone fresh creates a clean agent and keeps the source active.
  • Clone with handoff creates and starts a fresh agent with the source semantic result, operational-state counts, and copied PR catalog.
  • Archive when safe opens a confirmation view. Archive stays unavailable for a running agent, an unresolved inquiry, or ordinary queued work.

The source agent keeps delegation ownership, queued work, inquiries, schedules, PR references, logs, and audit history. The TUI and Remote UI now keep the source by default during a clone.

Verification

  • Domain tests cover Codex measured pressure, stale data, Claude and Pi compaction, acknowledgement, and unsupported harnesses.
  • Archive tests cover ordinary queues, mixed queues, callback history, and unresolved inquiries.
  • API tests cover a durable handoff clone that keeps the source agent.
  • A real Chrome run at 1440×900 and 390×844 verified the alert text, four actions, archive confirmation, acknowledgement, and responsive bounds.
